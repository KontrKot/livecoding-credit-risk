# Задание: Credit Risk Pre-Check Service

## Контекст

Компания выдаёт онлайн-кредиты. Перед выдачей кредита заявку необходимо проверить набором бизнес-правил, которые могут отклонить заявку (`ERROR`) или пометить её как повышенный риск (`WARN`).

## Цель

Реализовать **Credit Risk Pre-Check Service** — сервис, который прогоняет кредитную заявку через настраиваемый набор правил и формирует итоговый отчёт.

## Примеры правил

| Правило | Условие и Статус |
|---|---|
| Возрастное ограничение | `age < 18` = `ERROR` (автоотказ); `age < 21` = `WARN` (повышенный риск); `age >= 21` = `OK` (все хорошо); |
| Долговая нагрузка | `debt / income > 60%` = `ERROR`; `debt / income > 40%` = `WARN`|
| Страна под санкциями | `CountryBlacklistRule` = `ERROR`|

> Список правил не финален — бизнес может запрашивать новые правила в любой момент.

## Требования к сервису

1. **Гибкая настройка без рекомпиляции.** Поведение сервиса управляется конфигом (формат конфига — на ваш выбор: YAML/JSON/properties и т.д.). Конфиг управляет:
   - какие правила включены/выключены;
   - порядок исполнения правил;
   - остановка обработки после первого `ERROR` (fail-fast) или выполнение всех правил.
2. **Сбор статистики** *(дополнительное задание)*:
   - счётчик срабатываний каждого правила по статусам (`OK` / `WARN` / `ERROR`);
   - метод `topKFailingRules(k)` — топ-K правил, которые чаще всего дают `ERROR`.

## Модель данных

### Входная заявка на кредит

```java
/**
 * Входная заявка на кредит
 */
public class CreditApplication {
    private String applicationId;
    private String userId;
    private int age;
    private BigDecimal monthlyIncome;
    private BigDecimal monthlyDebt;
    private String country;
    private boolean vipClient;
}
```

### Результат применения правила

```java
/**
 * Результат применения бизнес-правила.
 */
public enum RuleStatus {
    OK,
    WARN,
    ERROR
}
```

### Результат выполнения одного правила

```java
/**
 * Результат выполнения одного правила для кредитной заявки.
 */
public class RuleResult {
    private String ruleId;
    private RuleStatus status;
    private String message;
}
```

### Итоговый отчёт

```java
/**
 * Итоговый отчёт проверки кредитной заявки бизнес-правилами.
 */
public class EvaluationReport {
    private String applicationId;
    private RuleStatus overallStatus; // OK если все правила OK;
                                       // WARN если хотя бы одно WARN;
                                       // ERROR если хотя бы одно ERROR
    private List<RuleResult> ruleResults;
}
```

## Что нужно сдать

- Реализацию сервиса проверки заявок (engine, набор правил, загрузка конфигурации).
- Минимум 3 готовых правила: возрастное ограничение, долговая нагрузка, `CountryBlacklistRule`.
- Конфигурационный файл с примером настройки (включение/выключение правил, порядок, fail-fast).
- (Доп.) Модуль статистики со счётчиками по статусам и `topKFailingRules(k)`.
- Юнит-тесты, покрывающие основные сценарии (OK / WARN / ERROR, fail-fast, отключённые правила).

## Критерии оценки

- Расширяемость: добавление нового правила не требует изменения ядра сервиса.
- Корректность вычисления `overallStatus`.
- Корректность работы fail-fast режима.
- Корректность и производительность `topKFailingRules(k)`.
- Чистота архитектуры (разделение ответственности между правилами, движком исполнения и конфигурацией).
